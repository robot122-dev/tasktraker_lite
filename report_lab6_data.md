# Данные для отчёта — Лабораторная работа №6

## Таблица нарушений SOLID

| Принцип | Как нарушен в исходном коде |
|---------|---------------------------|
| **SRP** | Класс `TaskManager` хранит задачи, создаёт/удаляет/редактирует их, работает с `localStorage`, генерирует HTML, выводит уведомления, выполняет поиск и фильтрацию — 8+ ответственности в одном классе. |
| **OCP** | Класс закрыт для расширения: добавление нового хранилища (REST API) требует изменения самого класса. |
| **LSP** | Нет базового класса или интерфейса. Подмена реализации невозможна без изменения клиентского кода. |
| **ISP** | Класс реализует все интерфейсы сразу. Клиенты вынуждены зависеть от методов, которые им не нужны. |
| **DIP** | Жёсткая зависимость от `localStorage`, `document`, `setTimeout`. Нет абстракций между модулями. |

## Таблица применения SOLID

| Принцип | Выполненные изменения | Результат |
|---------|----------------------|-----------|
| **SRP** | Разделение на `TaskService`, `LocalStorageRepository`, `NotificationService`, `HtmlRenderer` | Каждый класс можно менять независимо |
| **OCP** | Введены интерфейсы `ITaskRepository`, `INotificationService`, `IHtmlRenderer` | Новое хранилище добавляется без изменения `TaskService` |
| **LSP** | Все классы реализуют интерфейсы, подставляются через конструктор | Подмена компонентов работает через полиморфизм |
| **ISP** | Маленькие интерфейсы: `ITaskRepository` (7 методов), `INotificationService` (4), `IHtmlRenderer` (3) | Клиенты зависят только от нужных методов |
| **DIP** | `TaskService` зависит от интерфейсов, зависимости передаются через конструктор | Тестирование упрощается — подставляем моки |
